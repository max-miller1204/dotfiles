WATCHDOG THINKING: WHY "max" AND NOT "high"
===========================================

The pin is on opencode-go/kimi-k3, whose thinkingLevelMap in this machine's real pi
models store maps every level to null except max. The fork's getSupportedThinkingLevels
treats an explicit null as unsupported, so "high" resolves to nothing and the watchdog
would review with thinking OFF. Both configurations below are resolved by the fork's own
strict loader, not by re-implementing its rules.

kimi-k3 as the real store describes it:
  {
    "id": "kimi-k3",
    "reasoning": true,
    "thinkingLevelMap": {
      "off": null,
      "minimal": null,
      "low": null,
      "medium": null,
      "high": null,
      "xhigh": null,
      "max": "max"
    }
  }
